# خطة تطوير لوحة التحكم (CMS) — وزارة الثقافة السورية

> دراسة شاملة لواقع لوحة التحكم الحالية، مقارنتها بأنظمة CMS رائدة (WordPress، Strapi، Sanity، Directus)، وخطة تطوير مرتّبة بالأولوية. تم تنفيذ البنود ذات الأولوية القصوى مباشرة بعد كتابة هذه الخطة (انظر قسم "ما تم تنفيذه فعلياً" في الأسفل).

تاريخ الدراسة: 2026-06-08

---

## 1. ملخص الوضع الحالي (الجرد الداخلي)

لوحة التحكم مبنية على Next.js 16 (App Router) + Prisma/PostgreSQL، بنظام صلاحيات RBAC غني (8 أدوار: SUPER_ADMIN, ADMIN, EDITOR, AUTHOR, CONTRIBUTOR, VIEWER, EVENT_MANAGER, ACHIEVEMENT_MANAGER)، ولوحات تحكم مخصّصة لكل دور.

### ما هو موجود وقوي بالفعل ✅
| الميزة | الحالة |
|---|---|
| نظام أدوار وصلاحيات (RBAC) دقيق ومُطبّق على مستوى API + الواجهة | ممتاز — أدق من WordPress الافتراضي |
| محرر محتوى غني (RichTextEditor) + PageBuilder بصيغة بلوكات | جيد جداً، يضاهي Gutenberg |
| ترجمة آلية مدمجة (Google Translate API عبر `/api/admin/translate`) بحماية Rate-Limit | ميزة متقدمة لا تملكها معظم أنظمة الـ CMS الجاهزة افتراضياً |
| جدول منشورات بفلاتر/بحث/فرز/أزرار إجراءات جماعية (Bulk: نشر/أرشفة/مسودة/حذف) | على مستوى WordPress |
| مكتبة وسائط بحث + معاينة + نسخ الرابط | أساسية لكن تعمل |
| سجل تدقيق أمني (`AuditLog` model) لعمليات حساسة (إعادة تعيين كلمات المرور) | ممتاز كفكرة DB، لكن **بلا واجهة عرض** |
| إعدادات موقع مرنة (`Setting` model بمفاتيح/قيم/مجموعات) | جيد |
| تصميم متجاوب (Mobile drawer للقائمة الجانبية) + دعم RTL كامل | جيد |
| رؤوس أمان HTTP (CSP جزئي، X-Frame-Options، إلخ) + sanitization للمحتوى الغني | أعلى من المتوسط لمواقع حكومية |

### الفجوات المكتشفة ⚠️

1. **جرس الإشعارات في الشريط العلوي زخرفي بالكامل** — `AdminTopbar.jsx` يعرض أيقونة 🔔 بدون أي قائمة منسدلة أو مصدر بيانات أو نقطة حمراء فعلية. لا يوجد `Notification` model في قاعدة البيانات أصلاً.
2. **لا يوجد بحث شامل (Global Search / Command Palette)** — المستخدم مضطر للتنقل يدوياً بين الأقسام (منشورات، فعاليات، مستخدمين، وسائط) بدل البحث من مكان واحد. أنظمة حديثة مثل Sanity وNotion وLinear تعتمد على `⌘K` كنمط أساسي للتنقل السريع.
3. **سجل التدقيق (AuditLog) غير مرئي للإدارة** — البيانات تُسجَّل في القاعدة لكن لا توجد صفحة `/admin/audit-log` لعرضها أو تصفيتها. هذا يُفقد الميزة الأمنية القيّمة قيمتها العملية (خصوصاً بعد تدقيق الأمان الأخير الذي كشف عن محاولات تصعيد صلاحيات).
4. **لا يوجد سجل مراجعات/إصدارات للمحتوى (Revisions)** — على عكس WordPress الذي يحتفظ تلقائياً بنسخ سابقة من كل مقال ويتيح المقارنة والاستعادة. حالياً أي تعديل يستبدل المحتوى نهائياً دون أثر.
5. **لا يوجد حفظ تلقائي / استرجاع المسودات (Autosave / Draft Recovery)** — إغلاق المتصفح بالخطأ أثناء الكتابة الطويلة = فقدان كامل للعمل. `localStorage` غير مستخدم لهذا الغرض.
6. **النشر المجدول غير فعلي** — الحقل `publishedAt` موجود في النموذج (`datetime-local`)، لكن لا يوجد مجدوّل (cron/queue) يحوّل تلقائياً المنشور من DRAFT إلى PUBLISHED عند حلول الموعد. القيمة تُستخدم فقط للعرض.
7. **لا يوجد وضع داكن (Dark Mode)** للوحة التحكم رغم أنه أصبح معياراً متوقعاً في 2025-2026 لتقليل إجهاد العين أثناء جلسات التحرير الطويلة.
8. **مكتبة الوسائط بدائية نسبياً** — لا مجلدات/ألبومات لتنظيم آلاف الصور، لا تتبّع لاستخدام الملف ("أين تُستخدم هذه الصورة؟")، لا قص/تحرير صور مدمج، لا رفع متعدد بالسحب والإفلات بشكل واضح.
9. **لا اختصارات لوحة مفاتيح (Keyboard Shortcuts)** لتسريع عمل المحرّرين المتمرّسين (حفظ، نشر، بحث، تنقل).
10. **لوحة المعلومات (Dashboard) إحصائية فقط** — لا رسوم بيانية/اتجاهات زمنية (مثل: نمو المنشورات شهرياً، أكثر التصنيفات نشاطاً)، رغم وجود البيانات الكافية لذلك.

## 2. دراسة المنافسين (أنظمة CMS مرجعية)

| النظام | نقاط القوة التي يمكن الاستفادة منها |
|---|---|
| **WordPress** | سجل المراجعات (Post Revisions) مع مقارنة ودمج، النشر المجدول الفعلي، الحفظ التلقائي كل 60 ثانية، شريط إشعارات/تحديثات، نظام إضافات ضخم |
| **Strapi** | لوحة أدوار وصلاحيات مرئية (Role & Permission matrix UI)، سجل تدقيق (Audit Logs) كميزة Enterprise جاهزة بواجهة فلترة قوية، Webhooks |
| **Sanity Studio** | بحث شامل فوري (`⌘K` Command Palette) يغطي كل أنواع المحتوى، تتبّع التغييرات اللحظي (Real-time presence)، عرض "من يُحرر ماذا الآن" |
| **Directus** | لوحة بيانات قابلة للتخصيص بمخططات بيانية (Insights/Dashboards مع widgets قابلة للسحب)، إدارة وسائط بمجلدات + بحث بالعلامات (tags) |
| **Notion / Linear** | اختصارات لوحة مفاتيح شاملة وواضحة، أوضاع داكنة أنيقة افتراضية، إشعارات داخلية لحظية عبر مركز إشعارات موحّد |

**الخلاصة:** البنية التحتية لـ CMS الوزارة (الصلاحيات، الأمان، البلوكات، الترجمة الآلية) تتفوق فعلياً على نقاط انطلاق هذه الأنظمة في جوانب معينة. لكنها تفتقر لطبقة "تجربة الاستخدام اليومي المتقدّمة" التي تجعل العمل أسرع وأكثر أماناً وأقل توتراً — وهذه بالضبط الفجوات المذكورة أعلاه.

## 3. خطة التطوير المرتّبة بالأولوية

### المرحلة 1 — أولوية قصوى (قيمة عالية / جهد منخفض-متوسط) — **نُفِّذت ضمن هذه الجلسة**
1. ✅ **مركز إشعارات حقيقي** في الشريط العلوي (نموذج بيانات + واجهة قائمة منسدلة + عداد غير مقروء)
2. ✅ **صفحة سجل التدقيق** `/admin/audit-log` لعرض/تصفية الأحداث الأمنية المسجَّلة فعلياً في `AuditLog`
3. ✅ **حفظ تلقائي محلي (Draft Recovery)** للمحرر — حماية من فقدان العمل عند الإغلاق العرضي

### المرحلة 2 — أولوية عالية (تحسينات تجربة استخدام يومية)
4. بحث شامل / لوحة أوامر (`⌘K`) تغطي المنشورات والفعاليات والمستخدمين والوسائط
5. سجل مراجعات للمحتوى (حفظ نسخة عند كل تعديل جوهري + إمكانية المقارنة/الاستعادة)
6. وضع داكن للوحة التحكم بالكامل (مع تذكّر تفضيل المستخدم)

### المرحلة 3 — تحسينات متوسطة الأجل
7. نشر مجدول فعلي (مهمة دورية/cron تتحقق من `publishedAt` المستقبلي وتُفعّل النشر تلقائياً)
8. مكتبة وسائط محسَّنة: مجلدات، تتبّع الاستخدام، رفع بالسحب والإفلات بشكل أوضح
9. اختصارات لوحة مفاتيح أساسية (حفظ Ctrl+S، بحث Ctrl+K، إلخ) مع نافذة مساعدة تعرضها
10. رسوم بيانية في لوحة المعلومات (اتجاهات شهرية، أكثر التصنيفات نشاطاً) باستخدام البيانات الموجودة فعلاً

## 4. ما تم تنفيذه فعلياً (المرحلة 1 — مكتملة)

تفاصيل التنفيذ موثّقة كتعليقات داخل الكود نفسه. أهم النقاط:

- **نموذج `Notification` جديد في Prisma** مرتبط بالمستخدم المستهدف، مع نوع/عنوان/رابط وحالة قراءة، وتمت مزامنته بأمان عبر `prisma db push` (الطريقة الإضافية الآمنة، دون فقدان أي من الـ 419 سجل بيانات حقيقية).
- **API كامل** (`/api/admin/notifications`, `/api/admin/notifications/[id]/read`, `/api/admin/notifications/read-all`) مع تطبيق صلاحيات الجلسة (`verifySession`) وتقييد كل مستخدم لإشعاراته فقط.
- **واجهة منسدلة فعلية** في `AdminTopbar` تعرض آخر الإشعارات مع نقطة حمراء للعدد غير المقروء، وتتيح وضع علامة "مقروء" فردياً أو جماعياً.
- **صفحة `/admin/audit-log`** (مقتصرة على SUPER_ADMIN/ADMIN عبر صلاحية جديدة `VIEW_AUDIT_LOG`) تعرض سجل التدقيق الأمني مع تصفية حسب نوع الحدث، وتُبرز الإجراءات الحساسة بصرياً.
- **حفظ تلقائي محلي في محرر المنشورات** (`localStorage`) يحفظ نسخة من العنوان/الملخص/المحتوى كل بضع ثوانٍ من التعديل غير المحفوظ، ويعرض شريطاً لاسترجاعها عند العودة لصفحة لم تُحفظ تغييراتها.

> ملاحظة: تم اختيار هذه البنود الثلاثة تحديداً للتنفيذ الفوري لأنها (أ) الأعلى قيمة فعلية من حيث سد فجوة أمنية/تشغيلية ملموسة، و(ب) قابلة للتنفيذ الآمن دون أي تعديل جذري على البنية الحالية أو مخاطرة على البيانات الحية.

### التحقق (Verification)

تم تشغيل اختبار تكاملي عبر HTTP حقيقي (حساب اختبار مؤقت + ملفات تعريف ارتباط جلسة، تم حذفه بالكامل بعد الانتهاء) غطّى:
- تسجيل الدخول، وظهور إشعار مزروع في `GET /api/admin/notifications` مع عدّاد غير مقروء صحيح
- تعليم إشعار كمقروء وتثبّت الحالة في قاعدة البيانات
- **رفض** محاولة مستخدم آخر تعليم إشعار ليس له بـ `403` (فحص الملكية)
- وصول `SUPER_ADMIN` لصفحة `/admin/audit-log` (`200`) مقابل **إعادة توجيه** حساب `VIEWER` بعيداً عنها (`307`) — يثبت أن `VIEW_AUDIT_LOG` مُطبَّقة فعلياً وليست تجميلية فقط

كل الفحوصات (7/7) نجحت. تم تشغيل الخادم محلياً والتأكد من تصدير وتجميع كل الصفحات والمكوّنات الجديدة دون أي خطأ في وقت البناء (`✓ Compiled` لكل المسارات المعدَّلة، بما فيها محرّرا المنشورات والإنجازات بعد إضافة منطق الاسترجاع المحلي).
